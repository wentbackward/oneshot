Build a modular, browser-based 2048 game application with an integrated AI auto-solver, built in TypeScript and bundled as a static web app with a full automated unit test suite (node:test or Vitest).

1. Architecture & Module Separation
- Separate pure game logic (`src/engine/`) from AI solver logic (`src/ai/`) and DOM/Canvas rendering (`src/ui/`). All game rules and AI algorithms must be headless-testable without a DOM.
- Support optional seeded PRNG injection into the game engine so board initialization and tile spawns are 100% deterministic in tests.

2. Core Game Engine & Rules
- Configurable grid size (default 4x4, plus 3x3 and 5x5 modes).
- Slide mechanics in 4 directions (Up, Down, Left, Right): tiles slide until blocked; identical adjacent tiles merge once per move (e.g., `[2, 2, 2, 2]` sliding left becomes `[4, 4, 0, 0]`, and `[4, 2, 2, 0]` becomes `[4, 4, 0, 0]`).
- Spawn a new tile (90% `2`, 10% `4`) on a random empty cell ONLY when the move actually changed the board state.
- Maintain a move history stack supporting up to 10 levels of Undo (restoring board state and score).
- Track win state (reaching target tile 2048, allowing "Keep Playing") and game-over state (no empty cells and zero valid orthogonal merges).
- Persist current game state, undo stack, and per-grid-size Best Score in `localStorage` with graceful fallback if storage is unavailable/corrupted.

3. AI Auto-Solver (`src/ai/`)
- Implement an Expectimax search solver with configurable depth (Fast: depth 2, Balanced: depth 4, Deep: depth 6) and a weighted heuristic evaluating empty cell count, board monotonicity, smoothness, and corner-anchoring of the highest tile.
- Expose a "Hint" action (highlights the AI's recommended next move) and an "Auto-Play" toggle with adjustable move speed (50ms to 1000ms per step) that pauses cleanly on win/game-over or manual user input.

4. UI & Controls
- Responsive board with smooth CSS/transform animations for tile sliding, merging (pop scale), and spawning.
- Keyboard controls (Arrow keys, WASD, `Z` for Undo, `R` for Restart, `Space` to toggle AI Auto-Play) plus mobile touch swipe support.
- Display live telemetry when AI mode is active: current search depth, evaluated nodes per move, and heuristic board score.

5. Verification & Checks
- Unit tests covering single-merge chain edge cases, no-op move spawn prevention, win/game-over boundary conditions, undo state integrity, and AI solver avoiding immediate invalid moves.
- Typecheck (`tsc --noEmit`) and production build check must pass cleanly.



6. Visual Direction & Media Design (standing requirement)

Before any visual work on this product starts, the digital-media-designer skill
(asset-forge toolchain) defines and documents the overall look and feel:

- Style and a one-sentence concept line for the world and mood.
- Colour palette per theme: a named hex list per selectable theme (pixel art:
  8-32 colours, the spec's `palette`; every pixel asset snaps to it). Tile and
  piece colours follow a deliberate contrast ramp by magnitude; the board
  recedes, the tiles pop.
- Consistency anchors: light direction, outline policy, detail level.
- Required assets and animation direction: for every element that moves —
  what moves, how, frame count and cadence, easing (tile spawn, merge pop,
  slide).
- The palette/theme definitions are part of each ticket's acceptance
  criteria; final image assets follow docs/ASSET-SOURCING.md (where
  applicable).
